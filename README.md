# Система учёта инструментов (QR Tool Tracker)

Веб-приложение на Flask для выдачи и возврата инструментов по QR-коду.
Сотрудник один раз входит по табельному номеру и паролю (система запоминает
его на телефоне надолго). После входа ему доступна страница «Инструменты» —
список всех инструментов (свободен / когда освободится, без указания того,
кто именно держит чужой инструмент) и отдельно то, что сейчас на руках у
него самого. Само взятие инструмента по-прежнему происходит только через
сканирование QR-кода на самом инструменте — со страницы списка взять нельзя,
это осознанно (см. «Осознанные упрощения» ниже). Администратор входит
отдельно и управляет каталогом инструментов, сотрудниками (в т.ч. выдачей
им паролей), QR-кодами, историей и журналом действий.

## Стек

Flask · Flask-SQLAlchemy · Flask-Migrate (Alembic) · Flask-Login ·
Flask-WTF · SQLite · qrcode/Pillow · waitress. Без сторонних CSS/JS
фреймворков — один файл стилей (`app/static/css/style.css`).

## Первый запуск (Windows, PowerShell)

```powershell
cd "C:\VS Code\SOIVM\qr_tool_tracker"

python -m venv venv
venv\Scripts\activate

pip install -r requirements.txt

copy .env.example .env
# откройте .env и задайте свой SECRET_KEY, например:
python -c "import secrets; print(secrets.token_hex(32))"

# создать таблицы в базе данных
flask db upgrade

# создать первого администратора (спросит пароль)
flask create-admin admin "Имя Фамилия"

# запуск для разработки (с автоперезагрузкой)
python run.py
```

Приложение будет доступно на http://localhost:5001

Сотрудник открывает `http://<адрес>:5001/tool/<QR-код>` (это и есть ссылка,
зашитая в QR-код каждого инструмента — страница `Инструменты → QR-коды` в
админке). Если сотрудник ещё не входил — система сначала попросит табельный
номер и пароль (их выдаёт администратор при добавлении сотрудника), а дальше
будет помнить его на этом телефоне подолгу (см. `EMPLOYEE_REMEMBER_DAYS`
в `.env`).

## Перенос данных из старой версии проекта

Если нужно перенести пользователей/инструменты/заявки из старого проекта
(`SOIVM/projectArchive/qr_tool_tracker`), после `flask db upgrade`, но
**на пустую базу**, один раз выполните:

```powershell
python scripts\migrate_old_data.py "C:\VS Code\SOIVM\projectArchive\qr_tool_tracker\instance\tool_tracker.db"
```

Скрипт переносит инструменты и сотрудников без дублей (проверяет по
QR-коду / email / табельному номеру), поэтому его можно перезапускать.
Заявки же создаются заново при каждом запуске — не запускайте его дважды
на одной и той же базе.

Перенесённые сотрудники не имеют пароля (в старой системе авторизации не
было). Сразу после переноса выполните:

```powershell
python scripts\set_temp_passwords.py
```

Это выдаст временный пароль каждому сотруднику без пароля и сохранит
список в файл `instance\temp_passwords_<дата>.txt` (кириллица в консоли
Windows может отображаться некорректно — открывайте файл в блокноте).
Передайте пароли лично и удалите файл. Сотрудников без табельного номера
скрипт пропустит — сначала впишите им номер в админке (Сотрудники →
Изменить), потом запустите скрипт ещё раз.

## Пароли сотрудников

Администратор — единственный, кто заводит сотрудников и выдаёт им пароль:
при добавлении сотрудника (или по кнопке «Сбросить пароль» в списке
сотрудников) система сама генерирует временный пароль и один раз показывает
его в сообщении на экране — сообщите его сотруднику лично. При первом входе
с временным паролем сотрудника сразу перекидывает на смену пароля.

Своё "Сменить пароль" сотрудник может открыть в любой момент — ссылка есть
в шапке сайта, когда он вошёл.

## Повседневная работа

```powershell
venv\Scripts\activate
python run.py
```

При изменении моделей данных (`app/models.py`) создайте миграцию:

```powershell
flask db migrate -m "краткое описание изменения"
flask db upgrade
```

Управление администраторами — только через терминал (осознанно, без формы
в браузере):

```powershell
flask create-admin <логин> "Имя Фамилия"
flask reset-admin-password <логин>
```

Если в консоли Windows кириллица отображается кракозябрами — это не баг
приложения (в браузере всё будет читаться нормально), просто выполните
`chcp 65001` перед запуском команд.

## Запуск «по-боевому» (без режима отладки)

```powershell
python wsgi.py
```

Использует waitress — обычный, надёжный WSGI-сервер на чистом Python,
без сложностей с gunicorn под Windows. Порт и адрес можно переопределить
переменными окружения `HOST` / `PORT`.

Когда проект будет размещён на сервере с доменом — перед приложением
нужно поставить веб-сервер с HTTPS (рекомендуется **Caddy**: он сам
получает и продлевает сертификат Let's Encrypt, конфиг занимает
несколько строк). Не забудьте также:
- изменить `SECRET_KEY` и `SITE_URL` в `.env` на реальные,
- настроить регулярное резервное копирование `instance/tool_tracker.db`.

```
  static/        — css/style.css (вся дизайн-система), js/main.js (минимум)

  migrate_old_data.py    — разовый перенос данных из старого проекта
  set_temp_passwords.py — разовая выдача временных паролей перенесённым сотрудникам
migrations/     — история изменений схемы БД (Flask-Migrate/Alembic)
config.py, run.py, wsgi.py — конфигурация и точки входа
```

## Как устроена авторизация (для тех, кто будет дорабатывать)

И администратор, и сотрудник — это два разных класса (`Admin`, `Employee`
в `app/models.py`), но оба логинятся через один и тот же Flask-Login. Чтобы
Flask-Login не перепутал администратора №3 с сотрудником №3, `get_id()`
каждой модели возвращает id с префиксом роли (`"admin:3"` / `"employee:3"`),
а `user_loader` в `app/__init__.py` эту метку читает обратно. У каждой
модели есть простой атрибут `role` ("admin"/"employee") — именно по нему,
а не по одному только факту входа, каждый блюпринт в своём
`before_request` решает, кого пускать:

- `app/admin/__init__.py` — пускает только `role == "admin"`
- `app/employee/__init__.py` — пускает только `role == "employee"`

Если добавите третью роль (например, "мастер участка") — заведите такой же
`role`-атрибут и такую же проверку, шаблон уже отработан.

## Осознанные упрощения (чтобы не запутать в будущем)

- Заявка создаётся сразу в статусе "выдан", без отдельного этапа
  согласования — так и должно быть.
- Всё время в системе — московское (`app/utils/time.py`), без UTC и без
  конвертаций. Специально, чтобы не тащить сложность многочасовых поясов
  туда, где она не нужна.
- У сотрудника долгая сессия (`EMPLOYEE_REMEMBER_DAYS` в `.env`, по
  умолчанию 90 дней) — вход по паролю нужен редко, а не при каждом
  сканировании QR. У администратора сессия обычная.
- Вернуть инструмент может только тот сотрудник, которому он выдан, или
  администратор — коллеге, даже если он рядом стоит с телефоном, вернуть
  чужой инструмент нельзя (раньше это было можно, подобрав имя/фамилию).
- Страница «Инструменты» (`/tools`, `app/employee/routes.py`) — только
  просмотр статуса (свободен / когда освободится). Взять инструмент можно
  только сканированием QR-кода на нём самом — это осознанное решение
  (не техническое упрощение), страница специально не даёт кнопки "взять".
  Если понадобится это изменить — трогать нужно именно эту страницу,
  сам механизм взятия (`/tool/<code>/take`) менять не придётся.
- На этой же странице и на странице конкретного инструмента (`/tool/<code>`)
  для чужих (не своих) выданных инструментов не показывается, кто именно
  их держит — только дата, когда инструмент освободится. Это защита
  приватности сотрудников друг от друга; администратору в админке личность
  держателя видна как обычно.
